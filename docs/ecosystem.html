Architecture Philosophy: "Warp Thread" Modules

Each layer is designed as an independent "warp thread" module following these principles:

  • Protocol-Based Design: Components define abstract interfaces, not concrete implementations
  • Zero Inter-Dependencies: Modules don't import from each other, only from shared types
  • Graceful Degradation: Optional dependencies fail gracefully with fallbacks
  • Explicit Lifecycle: Async context managers ensure proper resource cleanup
  • Complete Provenance: Every decision is logged for debugging and improvement

HoloLoom ↔ Memory

Orchestrator queries memory systems (Neo4j/Qdrant/InMemory). Auto-fallback: if Neo4j unavailable, uses InMemory.

await hololoom.recall(query)

HoloLoom ↔ RAG

RAG system uses orchestrator for reasoning. Supports multimodal input through SpinningWheel adapters.

await rag.query(text, mode="verify")

HoloLoom ↔ Policy

Policy engine provides tool selection. Thompson Sampling adapts based on outcomes from reflection buffer.

action = policy.select_tool(features)

HoloLoom ↔ Alignment

Alignment framework gates all actions. Guardrails check safety, audit trail logs decisions.

ok = await guardrails.gate_action(action)

HoloLoom ↔ Promptly

Promptly integrates with LLM layer. Orchestrator can use Promptly-managed prompts for consistency.

prompt = promptly.load("my_prompt_v2")

HoloLoom ↔ Community

Community hub hosts examples, discussions, and issues. Feedback informs roadmap and development.
