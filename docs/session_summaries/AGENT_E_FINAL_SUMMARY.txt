API DESIGN
================================================================================

SimpleRAG.query_stream() Method:
  async def query_stream(
      self,
      question: str,
      mode: str = "direct",
      max_sources: int = 5
  ) -> AsyncGenerator[StreamToken, None]:
      """Stream response token-by-token."""

StreamToken Dataclass:
  @dataclass
  class StreamToken:
      text: str
      index: int
      cumulative_text: str
      metadata: Dict[str, Any]
      is_final: bool = False

Usage Example:
  async with SimpleRAG() as rag:
      await rag.ingest("Thompson Sampling...")

      async for token in rag.query_stream("What is Thompson Sampling?"):
          print(token.text, end='', flush=True)

          if token.is_final:
              print(f"\\nTokens/sec: {token.metadata['tokens_per_sec']:.1f}")

================================================================================
FEATURES IMPLEMENTED
================================================================================

1. Token-by-Token Streaming
   - Real-time output as tokens arrive
   - Support for Ollama, Anthropic, OpenAI
   - Works with any LLM provider that supports streaming

2. Metadata Tracking
   - Latency per token (running calculation)
   - Tokens per second metric
   - LLM provider identification
   - Final token flag with complete statistics

3. Cumulative Text
   - Full response text available via cumulative_text
   - Allows resuming from token position
   - Enables interactive UX with running summary

4. Graceful Fallback
   - Streaming unavailable? Fall back to regular query
   - Non-direct modes? Fall back to regular query
   - No LLM provider? Fall back gracefully
   - All failures logged appropriately

5. Automatic Caching
   - Skip cache for initial streaming query
   - Cache full response after streaming completes
   - Subsequent queries use cache (no streaming)

6. Mode Restriction
   - Only "direct" mode supports streaming
   - Other modes (verify, research, plan_execute) require multiple LLM calls
   - Non-direct modes automatically fall back

7. Error Handling
   - Custom StreamingError exception
   - Proper error messages for debugging
   - Graceful degradation on all failures

================================================================================
ARCHITECTURE DECISIONS
================================================================================

1. Mixin Pattern
   Why: Clean separation of concerns, easy testing, no core modifications
   How: StreamingRAGMixin provides query_stream() method
   Benefit: Can be independently tested and evolved

2. AsyncGenerator for Streaming
   Why: Proper async/await semantics, automatic resource cleanup
   How: AsyncGenerator[StreamToken, None] with yield statements
   Benefit: Memory efficient, real-time token delivery

3. Post-Streaming Caching
   Why: Cache full response for repeated queries
   How: Cache populated after streaming completes
   Benefit: Fast repeated queries without re-streaming

4. Mutable Token Metadata
   Why: Track running statistics as tokens arrive
   How: metadata dict updated on each token
   Benefit: Users can access real-time TPS and latency

5. LLM Provider Abstraction
   Why: Support multiple LLM providers
   How: Check orchestrator.llm_provider and call appropriate method
   Benefit: Works with Ollama, Anthropic, OpenAI, etc.

6. Comprehensive Fallback
   Why: Robustness and user experience
   How: Multiple fallback layers (streaming -> regular -> word-by-word)
   Benefit: Never fails, always delivers response
