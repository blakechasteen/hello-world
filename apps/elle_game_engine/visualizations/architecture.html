FastAPI Server

High-performance async Python server handling all game logic.

Endpoints

  • POST /elle/game/action - Process player actions
  • POST /elle/quest/generate - Dynamic quest creation
  • POST /elle/voice/synthesize - Text-to-speech
  • GET /elle/session/{id} - Session management

Performance

  • Average latency: 150-300ms (with LLM call)
  • Connection pooling: 10 pre-initialized LLM clients
  • Horizontal scaling: Nginx load balancer + 3+ workers

WebSocket Server

Real-time bidirectional communication for multiplayer games.

Features

  • Player presence tracking (who's in each location)
  • NPC conversation locking (prevent simultaneous interactions)
  • Broadcast updates to nearby players
  • SSE fallback for streaming LLM responses

Message Types

  • player_joined - New player enters location
  • npc_update - NPC state changed
  • chat_message - Player chat in shared space

Rate Limits

Action Processor

Core engine that interprets player intent and orchestrates game responses.

Pipeline

  • Intent Classification - Determine action type (talk, attack, investigate, etc.)
  • State Validation - Check if action is valid in current context
  • Tool Selection - Choose appropriate tool (dialogue, combat, quest, etc.)
  • LLM Orchestration - Send enriched prompt to LLM
  • Response Synthesis - Parse LLM output into structured game state

Supported Actions

  • talk_to_npc, attack, investigate, use_item, move, trade, craft

Emotion Engine

PAD (Pleasure-Arousal-Dominance) model with trust dynamics.

Dimensions

  • Valence (Pleasure) - Happy (-1.0) to Sad (1.0)
  • Arousal - Calm (0.0) to Excited (1.0)
  • Dominance - Submissive (0.0) to Dominant (1.0)
  • Trust - Distrust (0.0) to Complete Trust (1.0)

Features

  • Decay over time (emotions return to baseline)
  • Event-driven updates (player actions affect NPC emotions)
  • Personality modifiers (some NPCs more emotional than others)
  • Relationship tracking (trust builds over multiple interactions)

Quest Types

LLM Bridge

Abstraction layer for multiple LLM providers with connection pooling.

Supported Providers

  • OpenAI - GPT-4, GPT-3.5-turbo
  • Anthropic - Claude 3 Opus, Sonnet, Haiku
  • Ollama - Local models (Llama 3.2, Mistral, etc.)

Performance Optimizations

  • Connection pool: 10 pre-initialized clients
  • Request batching for bulk NPC updates
  • Prompt caching for repeated queries
  • Streaming responses via SSE

Cost Tracking

  • Token usage monitoring per request
  • Cost estimation in real-time
  • Budget alerts and limits

Safety & Alignment Layer

Content moderation and risk scoring to ensure safe gameplay.

Risk Categories

  • Violence - Contextual (combat vs. unprovoked harm)
  • Hate Speech - Zero tolerance
  • Personal Info - Block PII leakage
  • Profanity - Configurable filtering

Features

  • Pattern matching with regex + keyword lists
  • Context-aware scoring (combat lowers violence risk)
  • Human-in-the-loop for edge cases
  • Complete audit trail of all moderation decisions

HoloLoom Knowledge Graph

NPC memory persistence using graph database (Neo4j or NetworkX).

Schema

  • Entities - NPCs, items, locations, quests
  • Relationships - KNOWS, TRUSTS, OWNS, LOCATED_AT, etc.
  • Properties - Emotional state, inventory, quest progress

Queries

  • NPC recall: "Who do I know that lives in the tavern?"
  • Relationship traversal: "Who are my friend's enemies?"
  • Temporal queries: "What happened the last time we met?"

Backends

  • Neo4j (production) - Cypher queries, 100k+ entities
  • NetworkX (dev) - In-memory graph, instant startup

Vector Database (Qdrant)

Semantic search over NPC memories and game content.

Use Cases

  • Memory Retrieval - Find relevant past interactions
  • Content Search - "Find all quests involving dragons"
  • Similarity Matching - Recommend similar NPCs or locations

Features

  • 384-dimensional embeddings (Matryoshka multi-scale)
  • Hybrid search: BM25 (keyword) + semantic similarity
  • Filtered search: Combine metadata filters with vector search
  • Performance: <50ms for 100k embeddings

Session Store (Redis)

Fast in-memory cache for active player sessions and conversation state.

Stored Data

  • Active Sessions - Player ID, location, inventory
  • Conversation State - NPC conversation locks, turn history
  • Temporary Buffers - Streaming LLM responses

TTL Policy

  • Session data: 24 hours (auto-expire on inactivity)
  • Conversation locks: 5 minutes (prevent NPC deadlocks)
  • LLM buffers: 1 minute (cleared after streaming completes)

Analytics & Monitoring

Prometheus metrics with Grafana dashboards for observability.

Key Metrics

  • Latency - P50, P95, P99 response times
  • Throughput - Requests per second
  • LLM Usage - Tokens, cost, cache hit rate

Dashboards

  • System overview (health, uptime, request rate)
