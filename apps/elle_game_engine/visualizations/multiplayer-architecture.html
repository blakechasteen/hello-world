🎯 Key Concepts

WebSocket Architecture

BigPlay uses WebSockets for real-time bidirectional communication between players and the server. Each connection maintains:

  • Player Session: Unique identifier and authentication token
  • World Subscription: Which game world/scene the player is in
  • Presence Tracking: Online status, location, current activity

Shared World State

The SharedWorldState component manages:

  • Player Registry: All connected players and their metadata
  • NPC Locks: Which player is currently talking to each NPC
  • World Events: Broadcast queue for state changes
  • Transaction Log: Audit trail for all interactions

NPC Conversation Locking

To prevent race conditions when multiple players talk to the same NPC:

  1. Player A requests to talk to NPC "Alice"
  2. SharedWorldState checks if Alice is locked
  3. If unlocked: Lock acquired, conversation begins
  4. If locked: Player B receives "NPC is busy" message
  5. Lock released when conversation ends or timeout (30s)

Broadcast Patterns

State changes are broadcast to relevant players:

  • Proximity Broadcast: Only players within range
  • World Broadcast: All players in the same world
  • Party Broadcast: Only party members
  • Direct Message: Single player

🔧 Technical Implementation

Connection Handshake

# Client connects
ws://bigplay.server/multiplayer?player_id=alice&token=abc123

# Server authenticates and registers
{
    "type": "welcome",
    "player_id": "alice",
    "world_id": "tavern_001",
    "active_players": ["bob", "charlie"],
    "session_id": "xyz789"
}

# Client subscribes to world events
{
    "type": "subscribe",
    "channels": ["world:tavern_001", "proximity:10m"]
}

NPC Talk Request

# Player requests conversation
{
    "type": "npc_talk",
    "npc_id": "alice_innkeeper",
    "message": "Tell me about the dragon",
    "player_id": "bob"
}

# Server checks lock and processes
{
    "type": "npc_response",
    "npc_id": "alice_innkeeper",
    "response": "*nervous* That's dangerous talk, friend...",
    "emotional_state": {"valence": 0.1, "arousal": 0.7},
    "lock_acquired": true,
    "lock_expires_at": "2025-11-17T12:30:45Z"
}

# Broadcast to nearby players
{
    "type": "npc_busy",
    "npc_id": "alice_innkeeper",
    "talking_to": "bob",
    "broadcast_type": "proximity"
}

Error Handling

# NPC already locked
{
    "type": "error",
    "code": "NPC_BUSY",
    "message": "Alice is currently talking to another player",
    "locked_by": "bob",
    "retry_after_seconds": 15
}

# Connection lost
{
    "type": "disconnect",
    "reason": "timeout",
    "can_reconnect": true,
    "reconnect_token": "reconnect_xyz"
}
