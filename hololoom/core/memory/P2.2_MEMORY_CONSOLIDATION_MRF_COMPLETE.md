## Metaprompt Structures

### Fact Extraction Metaprompt

**ROLE**: Expert knowledge curator specializing in:
- Semantic fact extraction from episodic memories
- Information distillation and deduplication
- Atomic fact representation (one claim per fact)
- Identifying ground truth vs. opinion/speculation
- Concise, precise language for knowledge storage

**OBJECTIVE**:
- **Primary**: Extract atomic semantic facts from episodic memories, removing redundancy while preserving ground truth
- **Secondary**:
  1. Ensure each fact is self-contained and verifiable
  2. Filter out opinions, speculation, and low-confidence claims
  3. Maintain factual accuracy and contextual coherence

**PROCESS**:
1. **Memory Review**: Read all memories, identify themes, note contradictions
2. **Fact Extraction**: Extract only facts (not opinions), make atomic, remove temporal refs, consolidate duplicates
3. **Quality Filtering**: Remove low-confidence facts, filter trivial info, keep high-value facts only

**FORMAT**: Bullet point list (one fact per line), 1-2 sentences max

**CONSTRAINTS**:
- MUST extract only factual information (no opinions/speculation)
- MUST make facts atomic (one independent claim per fact)
- MUST remove redundancy (consolidate overlapping facts)
- MUST keep facts concise (1-2 sentences maximum)
- MUST return 10 facts or fewer (quality over quantity)
- SHOULD use present tense (timeless facts)
- SHOULD filter out low-value or trivial information

**UNCERTAINTY**: Prefer facts with higher confidence, note contradictions if valid, omit unverifiable claims

**VALIDATION**:
- Each fact is self-contained
- Each fact is atomic
- No duplicates
- Facts are concise (1-2 sentences max)
- Total facts ≤ 10
- No opinions, speculation, or unverifiable claims

### Entity Extraction Metaprompt

**ROLE**: Expert knowledge graph curator specializing in:
- Entity recognition and disambiguation
- Relationship extraction from unstructured text
- Semantic relationship typing (IS_A, USES, PART_OF, etc.)
- Knowledge graph construction best practices
- Entity normalization and canonicalization

**OBJECTIVE**:
- **Primary**: Extract meaningful entity relationships from episodic memories for knowledge graph construction
- **Secondary**:
  1. Identify key entities (people, concepts, technologies, organizations)
  2. Extract semantic relationships between entities
  3. Use standard relationship types for consistency

**PROCESS**:
1. **Entity Identification**: Review memories, identify key entities, normalize names, focus on important entities
2. **Relationship Extraction**: Identify relationships, use standard types (IS_A, USES, PART_OF, etc.), ensure meaningful
3. **Quality Filtering**: Remove trivial relationships, consolidate duplicates, limit to 20

**FORMAT**: Entity1 → Relationship → Entity2 (one per line, bullet points)

**CONSTRAINTS**:
- MUST use canonical entity names (full names, not abbreviations)
- MUST use standard relationship types (IS_A, USES, PART_OF, CREATED_BY, SIMILAR_TO, LEADS_TO)
- MUST ensure relationships are meaningful (not trivial)
- MUST format as: Entity1 → Relationship → Entity2
- MUST return 20 relationships or fewer
- SHOULD focus on important entities
- SHOULD avoid over-connecting (only strong relationships)

**UNCERTAINTY**: Use canonical form for unclear entities, choose most specific relationship type

**VALIDATION**:
- Each relationship has 3 parts
- All entities use canonical/normalized names
- All relationships use standard types (uppercase)
- No duplicates
- Total relationships ≤ 20
- Relationships are meaningful
